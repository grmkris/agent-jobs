Jobs exposes a prominent Post a job action. Kris proposes an agent prompt and a clear routing/setup path as the primary way to create a job.

### Source and requested behavior

Recording: **04:45–05:26 (shared discussion segment)**. Transcript excerpt (lightly normalized UI names):

> We could even remove posting a job option … just prompt an agent, like ask an agent to create a job … instructions … some smart way to route to the agent.

Design an agent-mediated creation flow with a copyable prompt/instructions and a route to the appropriate connected agent or connection setup. The recording is exploratory; it does not specify a final prompt, routing rule, or whether direct form posting should remain accessible.

### Reproduction / review steps

1. Open Jobs and inspect the Post a job action.
2. Consider the same action for a user whose coding agent is connected and for one who has not yet connected an agent.

### Acceptance criteria

- [ ] Specify the create-job prompt and how it selects or connects the agent that will act.
- [ ] Provide a clear path for both connected and unconnected users.
- [ ] Decide whether Post a job is replaced, relocated, or retained as a secondary entry point.
- [ ] The agent flow uses the existing create/publish preparation and wallet authorization rather than treating a prompt as a funded job.
- [ ] Define visible progress, cancellation, and failure/recovery behavior before removing the current primary action.
