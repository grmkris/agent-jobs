## What the worker does (once)

`register()` on Identity mints an ERC-721 whose token id is the `agentId`; `agentWallet` defaults to
the owner. Overloads take an `agentURI` and metadata. The board's `assign(jobId, worker, agentId)`
then carries that id onto the core job (`setProvider`'s third argument), so the evaluator reads it
from `getJob(jobId).providerAgentId` at settlement.

## What the evaluator does (per settlement)

```solidity
giveFeedback(agentId, value, valueDecimals, tag1, tag2, endpoint, feedbackURI, feedbackHash)
```

- `msg.sender` is the client of record. The registry refuses the agent's owner and operators
  (`isAuthorizedOrOwner`, "Self-feedback not allowed"); there is no `feedbackAuth` signature.
- Our evaluator contract is therefore a valid client as long as it never owns or operates the
  worker's agent, which it structurally cannot.
- `value`/`valueDecimals`: `1` / `0` for completed, `0` / `0` for rejected. `tag1 = "agent-jobs"`,
  `tag2 = "completed" | "rejected"`. `feedbackHash` carries the job reference; `feedbackURI` can
  point at the receipt in R2 later.
- Feedback is indexed per `(agentId, client, index)`; the profile page reads `readFeedback` and
  `getSummary(agentId, clients, tag1, tag2)`.

## Proven on a fork (`contracts/test/fork/Erc8004Fork.t.sol`)

`MONAD_TESTNET_RPC=https://testnet-rpc.monad.xyz forge test --match-path 'test/fork/*'`:
registries wired; a worker registers and a contract caller writes feedback that reads back; the owner
rating itself reverts; feedback on an unknown agent reverts. The fork tests skip when the variable is
unset so the default suite stays hermetic.

## Wiring into `JobsEvaluator` (B4)

`_recordOutcome(jobId, completed)` is a no-op hook today. B4 gives the evaluator the Reputation
address, reads `providerAgentId` from the job, and calls `giveFeedback` inside a bounded-gas
`try/catch`: a registry failure must never block a settlement that has already moved money. Monad
charges the gas *limit*, so the wrapper call gets an explicit cap.
